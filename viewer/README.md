# OpenDesk

OpenDesk is a unified Tauri desktop app: it can host incoming remote-control
sessions and connect to another OpenDesk instance as a viewer. Cryptography,
session keys, and the full transport stay in the Rust backend. Both host and
viewer gather/exchange ICE candidates and attempt direct UDP, falling back to
the encrypted relay. The WebView only decodes video with WebCodecs and captures
user input, making direct P2P bidirectional.

## Run

Start the relay, then run the app:

```bash
cargo run -p relay
cd viewer
npm install
npm run tauri dev
```

Each app generates and persists its own 9-digit device ID. A fresh one-time
session password is generated by the backend and can be rotated from Home;
there are no hardcoded IDs or passwords.

## Permissions

To host a controllable session on macOS, grant OpenDesk both permissions in
System Settings → Privacy & Security:

- Screen Recording, so the remote display can be captured.
- Accessibility, so remote mouse and keyboard input can be injected.

The Permissions screen reports the live status and opens the appropriate
settings pane. Incoming control is consent-gated: the host must Allow the
request before capture or input starts.

## Manual end-to-end check

1. Run two app instances, or run one instance on each of two machines, with
   both connected to the same relay.
2. On the host instance, note its generated ID and session password.
3. On the other instance, enter that ID and password and select Connect.
4. On the host, verify the requester and select Allow.
5. Confirm that the viewer sees the host screen and that mouse/keyboard input
   is delivered when the required permissions are granted.
6. Check the logs for `transport selected: direct` or `transport selected:
   relay`, then select Disconnect and verify both instances return to Home.

Remaining deferrals are graceful relay control-channel shutdown after Direct
is selected, audio, multi-monitor support, and file transfer.
